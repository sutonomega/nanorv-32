# 検証方針 — Draft 0.1

#7でコマンドと合格判定を確定する。現在は設計文書のみで、シミュレーション・合成・実機検証は未実施。

- ALU: 0、符号境界、桁あふれ、シフト0/31、signed/unsigned比較。
- CPU: 命令ごとのPC/レジスタ/メモリ、x0、分岐taken/not-taken、符号拡張、不正エンコード。
- バス/RAM: 同期読出し、可変待機、バイトストローブ、二重書込み防止、未割当、不整列、停止との競合。
- UART/起動: 正常、CRC破損、長さ超過、切断、再送、リセット復旧。
- C/OS: data/bss/スタック、容量超過、ロード/実行/終了/再操作。

テストはタイムアウト付きで自動判定し、失敗で非ゼロ終了する。命令トレースの参照モデル比較と既存アーキテクチャテストの導入は#7で検討する。採用した仕様版・対象範囲・除外理由を記録する。実機はビルド版・制約・資源量・タイミング・UARTログを保存する。文書追加を動作合格と扱わない。
